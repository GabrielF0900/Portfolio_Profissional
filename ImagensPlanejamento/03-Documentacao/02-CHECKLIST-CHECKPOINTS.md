# Checklist de validação por checkpoint

Após CADA fase, o Codex deve parar e entregar este relatório.

## 1. O que foi implementado
- seções/componentes concluídos;
- comportamento responsivo;
- motion implementado;
- funcionalidades preservadas.

## 2. Arquivos alterados
Listar arquivos criados, alterados e removidos.

## 3. Dados
Confirmar:
- dados reais preservados;
- nenhum projeto inventado;
- nenhuma métrica inventada;
- nenhuma certificação inventada;
- nenhuma tecnologia inventada;
- nenhum dado copiado de mockup sem validação.

## 4. Validações técnicas
Quando os scripts existirem:
- TypeScript;
- lint;
- build;
- testes;
- console/runtime.

## 5. O que o usuário deve revisar no navegador
Indicar exatamente:
- rota;
- seção;
- viewport desktop;
- viewport mobile;
- interações;
- hover;
- filtros;
- motion.

## 6. Diferenças deliberadas dos mockups
Explicar qualquer adaptação feita por:
- responsividade;
- acessibilidade;
- fidelidade aos dados reais;
- performance;
- limitações técnicas.

## 7. BLOQUEIO OBRIGATÓRIO
Depois do relatório, escrever:

`CHECKPOINT CONCLUÍDO — aguardando sua aprovação para continuar.`

E PARAR.

Não começar a próxima fase até o usuário responder explicitamente:

`CONTINUAR REDESIGN`
